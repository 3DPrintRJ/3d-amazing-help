Events

Events connect in-person selling activity to the craft show, market, fair, convention, festival, or pop-up where it happened. They help you separate immediate sales from orders taken for later, record Event-specific expenses, and estimate whether an Event was worthwhile.

Current beta documentation · Stage 1 Events foundation

Create an Event

  1. Open Events from the main navigation.
  2. Choose New Event.
  3. Enter the Event name, start and end dates, optional location/venue, and notes.
  4. Save the Event.

An Event can be Upcoming, Active, or Completed. Archiving hides an Event from normal use without deleting its history.

Current Event

One Event can be the Current Event. Use Make Current when you begin selling at a show. Quick Sales and new invoices automatically start with that Event selected, so you do not need to choose it on every transaction. You can still change or remove the Event on an individual transaction.

Choose Complete when the Event is finished. This clears its Current status while preserving every linked transaction and expense.

Quick Sales at Events

When a Current Event exists, Quick Sale prominently shows Selling at and the Event name. Completed Quick Sales keep that Event association.

Offline Quick Sale also keeps the cached Current Event. Sales saved while offline retain that Event when they sync after internet access returns.

Orders and invoices taken at Events

A custom order taken at a show uses the existing Invoice workflow; there is no separate Event-order system. A new Invoice can show Taken at with the Current Event. The Event remains attached while the Invoice later moves through Draft, Open, payment, fulfillment, or Paid status.

If a deposit is recorded on an Event-linked Invoice during the Event dates, the Event summary can show that deposit separately from completed sales and the remaining outstanding order value.

Customer acquisition source

A Customer can optionally record where that relationship originally came from: Event, Direct / Local, Referral, Etsy, Amazon, Website, or Other.

If a new Customer is created while a Current Event is active, 3D Amazing can prefill the Event as the acquisition source. This is the customer's original source. A later sale at a different Event does not replace it.

For example, Jane can remain Acquired at: Spring Craft Fair even when a later Holiday Market transaction is linked to Holiday Market. Customer source and transaction Event are separate concepts.

Event expenses

Use the Event's Expenses section for costs incurred specifically because you attended that Event, such as booth/vendor fees, travel or gas, hotel, parking, tolls, meals, supplies, Event advertising, electricity/Wi-Fi, permits, temporary labor, Event-specific insurance, or Other.

This is not a general company expense ledger. Normal rent, subscriptions, general insurance, and other ordinary overhead do not belong here unless they were specifically incurred because of the Event.

Event summary

The first Event summary separates:

  • Completed sales — completed paid Event transactions, excluding collected sales tax.
  • Orders / invoices taken — Event-linked invoices shown as activity rather than counted again as completed revenue.
  • Deposits collected at Event — posted Invoice payments dated during the Event.
  • Outstanding order value — remaining balance on Event-linked invoices.
  • Customers acquired — Customers whose original source is this Event.
  • Estimated product cost — stored product-cost snapshots for completed sales.
  • Event expenses — expenses entered specifically for the Event.

Estimated Event Result is a business decision estimate, not formal accounting profit. In Stage 1 it uses completed pretax sales minus product-cost snapshots and Event expenses. Selling/channel fees are added in the later Selling Channels stage.

Correcting an Event association

Open an Invoice or Receipt and change its Event when a transaction was linked to the wrong show. For finalized Invoices, this correction is recorded in the Invoice revision history.
