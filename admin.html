Founder administration

Users & Subscriptions

This page is available only to the 3D Amazing founder account. It combines authentication, plan, beta, and subscription information so account activity can be reviewed without cross-referencing Supabase and Stripe manually.

Founder-only documentation · Updated November 2, 2026

Compact administrative details

Email diagnostics now have optional explanation while the sender status/errors stay visible. Recent Activity and Deleted Accounts are expandable sections with record counts. The Users & subscriptions list and Public beta signup settings remain visible. Long submitted Roadmap descriptions now use Read full idea; publication decisions stay outside the expandable text.

Admin access

Admin still provides user, plan, beta and subscription records. Its mobile navigation uses the compact shared header and Menu while admin functions remain unchanged.

Admin list filters

The Users & Subscriptions search field remains visible on smaller screens, while View filters open from Filters & sort. Existing account, subscription, beta and activity data are preserved; the compact layout does not change billing or authentication status.

Summary cards

The top cards show Total Users, Free, Paid Plan, Active Subscribers, Beta Users, Never Signed In, and Active in 7 Days. Select a card to filter the user table.

Paid Plan versus Active Subscriber: Paid Plan means the business currently has paid access. Active Subscriber specifically means a live Stripe-managed subscription. Founder/test access can therefore appear as Paid without being counted as an active Stripe subscription.

User table

Review the account email, business name, plan, subscription status, beta status, signup date, last sign-in, last app use, and renewal/end date. A user who still has the temporary beta password requirement is also identified.

Search and filters

Search by email, business, plan, or subscription status. Filters are available for all users, Free, Paid, Active Subscribers, Beta Users, users who have never signed in, and users active in the last 7 days.

Recent user activity

The Access History section records successful authenticated sign-ins, sign-outs, and app-area activity from the release that introduced activity tracking onward. Earlier history continues to rely on Supabase’s last-sign-in timestamp. Failed password attempts are not attributed to a verified user.

Deleted accounts

Account Lifecycle records future Supabase account deletions from the date tracking was enabled. Earlier deleted test accounts are intentionally not reconstructed. When the deleting actor is not available from Supabase, the history shows that information as unavailable rather than guessing.

Public beta signup controls

The founder can open or pause limited public beta signup and set the maximum number of signup reservations for the current group. The panel shows reserved/joined count, remaining openings, and whether Turnstile security verification is configured. Public signup remains closed if the required security verification is not configured.

Security

The Admin menu is hidden for normal users, and the server independently verifies founder authorization before returning authentication or subscription data. Navigating directly to the Admin address does not grant access.

Document email status

The Admin page shows the built-in sender 3D Amazing <support@3damazing.com>, recent document-email attempts, and provider/domain diagnostics. A send-only Resend key can accept outgoing email while being unable to query domain settings, so the page distinguishes recent provider acceptance from independent domain-verification checks instead of treating the limited key as a sending failure.

Invite a security tester

In Admin → Users & Subscriptions, enter the test account email and business name in Invite a beta test account, then choose Send Invitation. The founder-only action reserves one available limited-beta place and asks Supabase to send a one-time invitation link. This does not open public beta signup or bypass Cloudflare verification for public visitors.

The recipient must open the emailed one-time link and choose a private password. A separate approved-beta business workspace is provisioned with the invitation; Practice is set up at first login. Never share a test password or use another person’s existing login for isolation testing. Confirm account creation in the Users list before performing cross-account security checks. A successful send request is not proof of email delivery; check Spam and verify that the tester has received the link. Invitation messages use the verified 3D Amazing email sender and contain a one-time link to app.3damazing.com/auth/confirm, where the tester verifies the invitation and continues to password setup. If the link is expired, invalid, or points at an obsolete Vercel address, enter the existing tester email in Admin and select Resend Setup Link; do not create another account. Never send a temporary password by email or chat.

Current scope

User/subscription records remain monitoring-only except limited-beta signup settings and founder-authorized email invitations. Passwords, plans, and billing records cannot be changed from this administration page.
